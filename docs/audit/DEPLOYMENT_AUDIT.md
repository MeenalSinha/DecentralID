## 1. Deployed Contract Address Inconsistency Investigation

A critical discrepancy was discovered across three locations in the repository:

| Source | Contract Address Recorded | Status / Analysis |
|---|---|---|
| `frontend/src/App.jsx:20` | `0xeB75C0d729AB514f4887440AA45BAc23F9fF1f89` | Hardcoded in React client, labelled "// ✅ DEPLOYED ON SEPOLIA" |
| `deployments/sepolia-deployment.json:3` | `0x4F9b33C607e54A8b87023ce4d837431F682E88e4` | Recorded by `scripts/deploy.js` on 2025-12-22T05:16:27.831Z |
| `.env.example:8` | `0x742d35Cc6634C0532925a3b844Bc9e7595f0bEb` | Invalid 39-hex-char address in example file |

### Evaluation:
- The address in `deployments/sepolia-deployment.json` (`0x4F9b33C607e54A8b87023ce4d837431F682E88e4`) was generated by `scripts/deploy.js` on Sepolia at block `9890826` by deployer `0xa8adD1f320637BCEE268fe589B99bCccAfe8e091`.
- However, someone subsequently hardcoded `0xeB75C0d729AB514f4887440AA45BAc23F9fF1f89` in `frontend/src/App.jsx` without updating the deployment metadata artifact.
- The `.env.example` address is truncated and invalid.

### Architectural Policy Established:
1. **Single Source of Truth:** Contract addresses must never be duplicated or hardcoded into client source files.
2. In the new architecture, deployment artifacts (`deployments/{network}-deployment.json`) will be generated directly during deployment. The backend reads this deployment manifest and serves the validated public addresses to the frontend via `/api/v1/blockchain/config`.
