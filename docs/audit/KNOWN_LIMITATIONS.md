# Phase 0: Known Limitations

**Project:** DecentralID  
**Date:** November 2026  

---

This document outlines the architectural and functional limitations identified during the Phase 0 audit of the initial repository.

## 1. Cryptographic and Credential Limitations
1. **Lack of Digital Signatures:** Credentials generated by the client are simple JSON representations containing no issuer digital signature. Anyone can fabricate or alter them without detection.
2. **No Issuer Public Key Infrastructure (PKI):** There is no on-chain or off-chain record of authorized signing keys belonging to institutions.
3. **Absence of Revocation Management:** Credentials cannot be suspended or revoked. Once an IPFS hash is linked to an identity, it remains permanently referenced without status checks.
4. **W3C Standard Non-Compliance:** Although the exported JSON references W3C schema contexts (`https://www.w3.org/2018/credentials/v1`), it does not follow the cryptographic data integrity standards (W3C Data Integrity 1.0 or ECDSA Cryptosuite).

## 2. Privacy Limitations
1. **Unencrypted IPFS Storage:** User profiles (name, bio, skills, education) are uploaded as unencrypted plain text to public IPFS gateways. Anyone who knows the hash can view all personal details.
2. **Correlatable On-Chain Identity:** User Ethereum addresses are directly tied to public profile IPFS hashes, completely eliminating pseudonymous privacy.

## 3. Smart Contract Limitations
1. **Monolithic Architecture:** `IdentityReputation.sol` conflates identity profile storage, reputation scoring, NFT-like endorsements, and issuer verification in a single contract.
2. **Gameable Reputation:** There is no rate limit, Sybil defense, or staking requirement on endorsement minting.
3. **Unchecked Owner Privileges:** A single owner account controls issuer verification without timelock or multisig safeguards.

## 4. Architectural and Operational Limitations
1. **No Backend API:** All logic is executed in the browser client or directly on Ethereum, precluding secure secret management, audit logging, rate limiting, and enterprise integrations.
2. **Zero Automated Tests:** No test suite was provided, creating high risk for regressions.
3. **No Continuous Integration (CI):** No automated builds, lints, or security scans existed in GitHub Actions.
